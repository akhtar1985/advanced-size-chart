How to read the source

What this page actually loads

The demo reproduces the storefront markup exactly: two JSON data blocks and a root div, followed by the widget script. That is also what the Liquid snippet outputs. 

<script type="application/json" id="asc-data-pg-inline">
  { "name": "Everyday Tee Size Guide", "tables": [ … ] }
</script>
<script type="application/json" id="asc-settings-pg-inline">
  { "displayMode": "inline", "defaultUnit": "cm", "primaryColor": "#111111", … }
</script>

<div class="asc"
     data-asc-root
     data-uid="pg-inline"
     data-mode="inline"
     data-variant-title="Fit|Regular|M"></div>

<script type="module" src="/size-chart.js"></script>
  • Variant matchingOn a product page the widget reads the selected options; here it uses data-variant-title split on |.
  • Unit memoryA toggle between cm and in persists in localStorage, so shoppers do not flip it every visit.
  • One vote per chartAfter a fit vote the buttons collapse to a thank-you line; votes are locked per chart in the browser.

Feedback votes on this static demo cannot reach the app proxy, so the request fails quietly. In a real store the widget posts to /apps/size-chart/feedback and the Worker records the tally.
